# Rail Restock · 矿车自动补料

[English](README.en.md) | 简体中文

Minecraft Java **1.21.11 / Fabric** 客户端 Mod。按所选 Litematica 投影材料清单的**全部剩余缺口**，从附近可正常交互的容器取料；可在矿车移动时持续扫描，默认以**无感模式**运行。

## 无感模式（0.2.0 默认开启）

自动补料时：

- **不弹出箱子界面**——只在本机取消那次容器界面的显示，服务端仍然正常开箱、正常同步库存。
- **不解锁鼠标、不改变视角**——因为界面从未真正打开，鼠标始终被游戏捕获。
- **不切换快捷栏选槽**——补料全程使用当前主手。箱子、陷阱箱、木桶、世界中的潜影盒这几种原版容器方块会直接消费这次右键并返回成功，手里的方块不会被放出去，所以不需要额外找空手或换槽。
- **不显示操作栏刷屏**——只在空闲时偶尔提示，搬运过程中界面保持干净。

代价是：补料瞬间仍会**极短暂停 Easy Place**——只覆盖真正搬运的那几个 tick（默认 `printPauseTicks = 6`，约 0.3 秒），不再等开箱同步和结算核对。暂停是**截止时间**而不是整次补料的锁：即使服务端同步变慢、结算超时，时间一到也会自动恢复打印，不需要重新按键，也不修改你的任何 Litematica 设置。

### 需要知道的两个前提

1. **补料时不要潜行**（潜行会取消方块交互转而使用手中物品）。检测到潜行或正在使用物品时，本次补料会跳过而不是冒险。
2. **补料时可以正常开背包**。打开背包、聊天等界面会让补料**自动暂停**（并安全关掉它开的容器），关掉界面的瞬间会自动继续，不需要重新按 F8。

## 功能

- **F8** 开关，可在「选项 → 控制 → 按键绑定 → 矿车自动补料」中改绑。
- **F7** 打开图形化设置界面（四个分页：交互 / 容器 / 节奏 / 提示），改动即时保存，含「恢复默认」；全部用原版控件，不需要 ModMenu 或 Cloth Config。
- 缺口来源是**当前选中并启用**的投影的材料清单，不合并其它投影。
- 支持箱子/陷阱箱、木桶、放在世界中的潜影盒；双箱只算一次。
- 使用玩家真实交互距离与视线碰撞：不增加距离、不隔墙取物、不走路、不控制矿车。
- 只搬清单需要的材料；物品按「物品 + 组件」精确匹配，不会只按名字合并。
- 背包优先合并到未满的同种堆，再使用空格；不使用护甲格、合成格、副手作为落点。
- **同一容器批量 Shift 取料**：使用原版 `QUICK_MOVE`，在同一 tick 连续处理所有需要的源槽位；最后不足一组的缺口才精确拆分，连续完成，不再逐个物品等待。
- 背包只剩部分容量时，若 Shift 转入的数量不超过缺口，同样使用快速转移；不会为了快速取物多拿整组。
- 每次结算后会在聊天与操作栏提示**具体取到什么、各多少个**，例如：`已取 圆石×64、橡木木板×32（共 96 个）`；操作栏摘要保留约 5 秒。
- 结算时在**当前容器会话内**请求服务端完整库存，同步核对背包增加量和容器减少量，确认后只关闭一次，**不再重开箱子核对**；客户端预测不算成功。
- **站在原地不反复检查相同容器**：无料、正常取完都保留访问记录，冷却到期不会再次开箱。离开该容器的交互范围（带 1 格缓冲）后才重新允许检查，双箱两半共用记录。因容量不足跳过的容器，仅在背包空间实际增加且能继续取物后允许重试，以支持原地打印、腾位后继续补料。F8 关闭再开启可立即重新检查周围容器，切换投影或统计范围也会重置记录。
- **共享 mapart-feeder 登记的原料容器**：直接用 `config/mapartfeeder.json` 里用 **K** 登记过的箱子，本 Mod 不需要再登记一次；该文件只读，绝不回写。
- **沿用 mapart-feeder 的翻箱顺序**：优先去已知含有缺口原料的箱子（按「可用数量 × 64 ÷ 距离」评分）；没开过的箱子按距离优先勘察；已知没有所需原料的箱子不再重复打开。
- **容器内容只在真正开箱、并拿到服务端完整库存后记录**，不隔空猜测；记录会自动过期（默认约 5 分钟），F8 关闭再开启则立即清空重勘。
- 未安装 mapart-feeder 时自动退回「扫描附近容器」的旧行为，功能不受影响。
- 材料清单沿用上游语义：倍数 1 用 `missing`，大于 1 用 `total × 倍数`，再减去一次 `available`；用户忽略项保留。
- 容器缺料或打不开时进入冷却，不会来回反复开关。

## 安装

1. 备份存档，先在测试环境验证。
2. 保持已有的 Fabric API、Litematica、MaLiLib 不变；不需要 Printer。
3. 把 `rail-restock-<版本>.jar` 放进游戏实例的 `mods` 目录（不要放 `-sources.jar`）。
4. 进入游戏，选中并启用要打印的投影，按原来的方式开启 Easy Place，再按 **F8**。

启动、断线、切换维度后自动补料默认关闭，不会记住开启状态。升级时请先退出游戏并移除旧版 JAR，不要两个版本共存。

## 设置界面（F7）

游戏内按 **F7** 打开，改绑位置与开关在同一分类下。界面分四页，每项都是原版控件，鼠标点一下即生效并立刻写入 `config/railrestock.json`；点「恢复默认」可还原全部默认值。

| 分页 | 内容 |
| --- | --- |
| 交互 | 无感开箱、暂停打印时长、开箱超时、同步超时、手动接管后等待 |
| 容器 | 共享 mapart-feeder 容器、只开登记的容器、缓存有效期、箱子/木桶/潜影盒开关 |
| 节奏 | 扫描间隔、分批间隔、取完后重查、无料冷却、容量不足重试、更新需求间隔 |
| 提示 | 自动重算材料清单、聊天提示、操作栏状态 |

- 界面本身不需要 ModMenu、Cloth Config 等额外依赖；没有安装它们也能打开。
- 打开界面会让正在进行的补料**自动暂停**（并安全关掉它开的容器），关闭界面后照常继续，与打开背包的行为一致。
- 数值项是滑条，范围就是配置允许的合法区间，不会写出越界值。

## 配置

首次启动生成 `config/railrestock.json`。多数项在游戏内按 **F7** 直接调整即可；手改文件请在退出游戏后进行。

| 字段 | 默认 | 说明 |
| --- | ---: | --- |
| `unobtrusiveInteraction` | `true` | 无感模式：隐藏自动打开的容器界面。设为 `false` 则显示箱子界面 |
| `autoRecountMaterialList` | `false` | 自动重算建筑缺失清单。默认关闭，本 Mod 不会自动触发统计（也就没有 Litematica 的「已添加任务」提示与 HUD 统计） |
| `scanIntervalTicks` | 5 | 空闲扫描间隔 |
| `clickIntervalTicks` | 2 | 极端拆分超出单 tick 的 128 包预算时，继续下一批的间隔；普通 Shift 批量不逐槽等待 |
| `openTimeoutTicks` | 40 | 开箱与完整库存等待上限 |
| `syncTimeoutTicks` | 60 | 预统计与确认等待上限 |
| `emptyContainerCooldownTicks` | 200 | 无料/打不开的容器，再次进入范围时的最小重试间隔；到期本身不会重置访问记录 |
| `successCooldownTicks` | 20 | 容量不足时重试的最小间隔，仍须背包空间实际增加 |
| `containerRevisitTicks` | 600 | 已取完容器再次经过时的最小重查间隔（默认 30 秒）；原地不因到期重查 |
| `recountIntervalTicks` | 200 | 空闲时更新建筑需求 |
| `manualPauseTicks` | 60 | 手动接管后的等待 |
| `printPauseTicks` | 6 | 暂停 Easy Place 的时长（tick）：每次槽位操作后只暂停这么久，约 0.3 秒，到点必然自动恢复 |
| `includeChests` / `includeBarrels` / `includeShulkerBoxes` | true | 扫描哪些容器 |
| `shareFeederContainers` | `true` | 读取 mapart-feeder 登记的容器（只读 `config/mapartfeeder.json`），并按其翻箱顺序选箱 |
| `onlyMarkedContainers` | `false` | 只开 mapart-feeder 登记过的箱子，绝不碰未登记的容器；需要先安装并登记 |
| `knowledgeExpireTicks` | 6000 | 已勘察容器内容的可信时长（约 5 分钟）；过期后重新勘察，避免箱子被补料后一直被跳过 |
| `chatNotifications` | true | 聊天提示 |
| `actionbarStatus` | true | 空闲时的操作栏状态 |

20 tick 约为正常服务器 1 秒。

### 关于自动重算清单

`autoRecountMaterialList` 控制**是否由本 Mod 自动触发 Litematica 的材料统计**。每次统计 Litematica 自己都会在聊天里打一行「已添加任务」，并在 HUD 上跑进度——这是它的提示，不是本 Mod 发的，所以只能通过不触发统计来消除。

- **关闭（默认）**：本 Mod 不再调度任何统计任务，除了补料瞬间的提示外几乎无打扰。此时它只用**已有的一次统计结果**计算缺口；建筑进度变化后缺口会偏大，可能多拿一点材料，需要你在 Litematica 里手动刷新一次清单来校正。
- **开启**：每次补料前、以及空闲时定期重算建筑缺失量，缺口最准。代价是会出现上述提示与 HUD 统计。

另外，每个投影**第一次**被本 Mod 读取时，Litematica 自己的懒加载仍会算一次（可能仍有一条提示），之后只要关闭该选项就不会再触发。

无论开关如何，补料成功后本 Mod 都会**静默**更新背包可用数量（这一步不触发 Litematica 提示，是防止重复搬料的关键）。

## 与 mapart-feeder 共享容器

两个 Mod 看到的是同一份登记表：mapart-feeder 用 **K** 在准星上登记的箱子会写进 `config/mapartfeeder.json`，本 Mod 读取其中的 `containers`（维度 + 坐标），所以**登记一次即可两边通用**。

- **只读**：本 Mod 不会修改或回写该文件，mapart-feeder 仍然是登记表的唯一所有者；你在游戏里按 K 新登记的箱子，本 Mod 最多 1 秒后就能看到，不需要重启。
- **选箱顺序**（沿用 mapart-feeder 的勘察逻辑）：
  1. 已知含有缺口原料的容器，按 `可用数量 × 64 ÷ (距离 + 1)` 从高到低；
  2. 尚未开过的容器，按距离由近到远，用来把内容勘察进缓存；
  3. 已知没有所需原料的容器直接跳过，不再打开。
- **内容缓存**只在真正开箱并拿到服务端完整库存、或取料结算的完整同步后写入；取走时同步扣减，所以同一容器不会被反复当成还有料。
- **时效**：缓存默认 5 分钟（`knowledgeExpireTicks`）后失效并重新勘察；F8 关闭再开启、切换投影或统计范围会立即清空。
- **只用登记容器**：把 `onlyMarkedContainers` 设为 `true`，就只开登记过的箱子，路过别人的箱子一概不动。
- 未安装 mapart-feeder 或文件不存在时，自动退回普通的附近扫描，不会报错。

补料本身仍然只发生在**当前交互距离内**：登记的箱子在远处不会被隔空打开，矿车经过时才取。

## 已知边界

- 未打开的容器内容无法提前知道，必须真的打开并等服务端同步；矿车速度过快时可能来不及，建议补料段减速或停靠。
- 拆分光标堆前要求背包能容下**整个可能拾起的光标堆**，为意外关箱留归位余量。因此背包只剩零星空间时，可能暂时不取最后几个。
- 当前会话的完整同步请求依赖 1.21.11 原版的过期库存版本校正机制。若服务端插件拒绝该请求，会在 `syncTimeoutTicks` 后结束，不重开、不重放取物、不把预测计为成功。
- 已检查过的空箱若被外部重新加料，客户端无法隔空得知；缓存约 5 分钟后失效并重新勘察，也可以按 F8 关闭再开启立即重查。
- 服务端强制关箱、其他插件改写库存等情况下，原版行为仍可能影响最终归位。中断后本 Mod 不把预测当作成功。
- 非原版容器方块（模组箱子等）只在主手为空时才会被尝试，避免误放物品。
- 隐藏界面是**纯客户端**行为：服务器看到的就是一次正常开箱。请仅在允许自动补料的世界或服务器使用。

## 构建

Windows 下执行：

```bat
build.cmd build
```

首次需要 `tools\prepare.cmd` 准备隔离的 Gradle 发行包。构建把 Gradle 缓存、Java 用户目录与临时目录都放在工程的上级（会话）目录，不污染系统目录。

产物：`build/libs/rail-restock-0.3.1.jar`。

## 备注

- 材料清单通过反射访问 Litematica 的公开 getter，**不依赖 `toNbt`/`toJson`** 这类版本相关的持久化接口，也不占用 Litematica 的单槽 completion listener。
- 本项目不包含 Litematica / MaLiLib / Fabric API，也不修改它们的文件。
