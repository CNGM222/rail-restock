# Rail Restock · 矿车自动补料

Minecraft Java **1.21.11 / Fabric** 客户端 Mod。按所选 Litematica 投影材料清单的**全部剩余缺口**，从附近可正常交互的容器取料；可在矿车移动时持续扫描，默认以**无感模式**运行。

## 无感模式（0.2.0 默认开启）

自动补料时：

- **不弹出箱子界面**——只在本机取消那次容器界面的显示，服务端仍然正常开箱、正常同步库存。
- **不解锁鼠标、不改变视角**——因为界面从未真正打开，鼠标始终被游戏捕获。
- **不切换快捷栏选槽**——补料全程使用当前主手。箱子、陷阱箱、木桶、世界中的潜影盒这几种原版容器方块会直接消费这次右键并返回成功，手里的方块不会被放出去，所以不需要额外找空手或换槽。
- **不显示操作栏刷屏**——只在空闲时偶尔提示，搬运过程中界面保持干净。

代价是：补料期间仍会**短暂暂停 Easy Place**。此时容器在服务端是打开的，若不互斥，打印和取料会争抢同一批槽位与物品。补料一结束立即解除，不修改你的任何 Litematica 设置。

### 需要知道的两个前提

1. **补料时不要潜行**（潜行会取消方块交互转而使用手中物品）。检测到潜行或正在使用物品时，本次补料会跳过而不是冒险。
2. **补料时可以正常开背包**。打开背包、聊天等界面会让补料**自动暂停**（并安全关掉它开的容器），关掉界面的瞬间会自动继续，不需要重新按 F8。

## 功能

- **F8** 开关，可在「选项 → 控制 → 按键绑定 → 矿车自动补料」中改绑。
- 缺口来源是**当前选中并启用**的投影的材料清单，不合并其它投影。
- 支持箱子/陷阱箱、木桶、放在世界中的潜影盒；双箱只算一次。
- 使用玩家真实交互距离与视线碰撞：不增加距离、不隔墙取物、不走路、不控制矿车。
- 只搬清单需要的材料；物品按「物品 + 组件」精确匹配，不会只按名字合并。
- 背包优先合并到未满的同种堆，再使用空格；不使用护甲格、合成格、副手作为落点。
- **一次开箱把该容器能给的料全部取完**，而不是拿一组就开关一次；期间连续处理多个槽位，最后只关箱/重开一次做总核对。
- 每次结算后会在聊天与操作栏提示**具体取到什么、各多少个**，例如：`已取 圆石×64、橡木木板×32（共 96 个）`。
- 结算时**正常关箱再重新开箱**，用服务端推来的完整库存核对实际转入数量，才会计入结果；客户端预测不算成功。
- 已经取空的容器会被**长时间跳过**（默认 30 秒），不会站着不动反复扫描、反复开同一个箱子。
- 材料清单沿用上游语义：倍数 1 用 `missing`，大于 1 用 `total × 倍数`，再减去一次 `available`；用户忽略项保留。
- 容器缺料或打不开时进入冷却，不会来回反复开关。

## 安装

1. 备份存档，先在测试环境验证。
2. 保持已有的 Fabric API、Litematica、MaLiLib 不变；不需要 Printer。
3. 把 `rail-restock-<版本>.jar` 放进游戏实例的 `mods` 目录（不要放 `-sources.jar`）。
4. 进入游戏，选中并启用要打印的投影，按原来的方式开启 Easy Place，再按 **F8**。

启动、断线、切换维度后自动补料默认关闭，不会记住开启状态。升级时请先退出游戏并移除旧版 JAR，不要两个版本共存。

## 配置

首次启动生成 `config/railrestock.json`，退出游戏后编辑，重启生效。

| 字段 | 默认 | 说明 |
| --- | ---: | --- |
| `unobtrusiveInteraction` | `true` | 无感模式：隐藏自动打开的容器界面。设为 `false` 则显示箱子界面 |
| `autoRecountMaterialList` | `false` | 自动重算建筑缺失清单。默认关闭，本 Mod 不会自动触发统计（也就没有 Litematica 的「已添加任务」提示与 HUD 统计） |
| `scanIntervalTicks` | 5 | 空闲扫描间隔 |
| `clickIntervalTicks` | 2 | 精确槽位操作间隔 |
| `openTimeoutTicks` | 40 | 开箱与完整库存等待上限 |
| `syncTimeoutTicks` | 60 | 预统计与确认等待上限 |
| `emptyContainerCooldownTicks` | 200 | 无料/打不开的容器冷却 |
| `successCooldownTicks` | 20 | 背包已满时该容器的短冷却 |
| `containerRevisitTicks` | 600 | 已取完的容器多久后才重新检查（默认 30 秒） |
| `recountIntervalTicks` | 200 | 空闲时更新建筑需求 |
| `manualPauseTicks` | 60 | 手动接管后的等待 |
| `includeChests` / `includeBarrels` / `includeShulkerBoxes` | true | 扫描哪些容器 |
| `chatNotifications` | true | 聊天提示 |
| `actionbarStatus` | true | 空闲时的操作栏状态 |

20 tick 约为正常服务器 1 秒。

### 关于自动重算清单

`autoRecountMaterialList` 控制**是否由本 Mod 自动触发 Litematica 的材料统计**。每次统计 Litematica 自己都会在聊天里打一行「已添加任务」，并在 HUD 上跑进度——这是它的提示，不是本 Mod 发的，所以只能通过不触发统计来消除。

- **关闭（默认）**：本 Mod 不再调度任何统计任务，除了补料瞬间的提示外几乎无打扰。此时它只用**已有的一次统计结果**计算缺口；建筑进度变化后缺口会偏大，可能多拿一点材料，需要你在 Litematica 里手动刷新一次清单来校正。
- **开启**：每次补料前、以及空闲时定期重算建筑缺失量，缺口最准。代价是会出现上述提示与 HUD 统计。

另外，每个投影**第一次**被本 Mod 读取时，Litematica 自己的懒加载仍会算一次（可能仍有一条提示），之后只要关闭该选项就不会再触发。

无论开关如何，补料成功后本 Mod 都会**静默**更新背包可用数量（这一步不触发 Litematica 提示，是防止重复搬料的关键）。

## 已知边界

- 未打开的容器内容无法提前知道，必须真的打开并等服务端同步；矿车速度过快时可能来不及，建议补料段减速或停靠。
- 拆分光标堆前要求背包能容下**整个可能拾起的光标堆**，为意外关箱留归位余量。因此背包只剩零星空间时，可能暂时不取最后几个。
- 服务端强制关箱、其他插件改写库存等情况下，原版行为仍可能影响最终归位。中断后本 Mod 会重新核对，不把预测当作成功。
- 非原版容器方块（模组箱子等）只在主手为空时才会被尝试，避免误放物品。
- 隐藏界面是**纯客户端**行为：服务器看到的就是一次正常开箱。请仅在允许自动补料的世界或服务器使用。

## 构建

Windows 下执行：

```bat
build.cmd build
```

首次需要 `tools\prepare.cmd` 准备隔离的 Gradle 发行包。构建把 Gradle 缓存、Java 用户目录与临时目录都放在工程的上级（会话）目录，不污染系统目录。

产物：`build/libs/rail-restock-0.2.0.jar`。

## 备注

- 材料清单通过反射访问 Litematica 的公开 getter，**不依赖 `toNbt`/`toJson`** 这类版本相关的持久化接口，也不占用 Litematica 的单槽 completion listener。
- 本项目不包含 Litematica / MaLiLib / Fabric API，也不修改它们的文件。
