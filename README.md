# Feeder Restock · 自动补料

[English](README.en.md) | 简体中文

Minecraft Java **1.21.11 / Fabric** 客户端 Mod。按所选 Litematica 投影材料清单的**全部剩余缺口**，从**mapart-feeder 登记过的容器**取料；玩家自己走位、自己决定何时补料，默认以**无感模式**运行，并在开箱前提前几 tick 让打印机停手。

## 只认 mapart-feeder 登记的容器

本 Mod **不会主动搜索周围的箱子**，也不再扫描附近方块：唯一允许的取料来源是 `config/mapartfeeder.json` 里由 mapart-feeder 登记过的容器。

- 用 mapart-feeder 的 **K** 对准箱子登记一次，两个 Mod 就共用同一份登记表；本 Mod **只读**该文件，绝不回写。
- mapart-feeder 没装、文件不存在、或登记表为空时，本 Mod 不会退回去乱翻周围的箱子，只会在状态里提示你需要先登记。
- 登记在远处的箱子不会被隔空打开：只有当你**自己走到交互距离内**时才会开箱取料。
- 双箱无论登记的是哪一半，都按同一个容器处理；顺序沿用 mapart-feeder 的勘察逻辑：已知有料优先，其次按距离勘察没开过的，已知没有所需原料的不再打开。

## 无感模式（默认开启）

- **不弹出箱子界面**——只在本机取消那次容器界面的显示，服务端仍然正常开箱、正常同步库存。
- **不解锁鼠标、不改变视角**——因为界面从未真正打开，鼠标始终被游戏捕获。
- **不切换快捷栏选槽**——补料全程使用当前主手。箱子、陷阱箱、木桶、世界中的潜影盒这几种原版容器方块会直接消费这次右键并返回成功，手里的方块不会被放出去。
- **不显示操作栏刷屏**——只在空闲时偶尔提示，搬运过程中界面保持干净。

## 打印暂停

**开箱前几 tick 就停**（`preOpenPauseTicks`，默认 5 tick ≈ 0.25 秒），接着覆盖开箱与搬运，搬完当即关箱，再短暂保持约 0.3 秒后自动恢复；整次补料受 `visitPauseCapTicks`（默认 40 tick ≈ 2 秒）硬上限保护，即使服务端同步变慢或结算超时也会自行恢复，不需要重新按键，也不修改你的任何 Litematica / 打印机设置。

暂停同时覆盖两条打印路径：Litematica 自带的 **Easy Place**，以及 **litematica-printer** 的打印模块（直接跳过它的每 tick 打印，不改动它的开关，所以界面上的打印指示不会来回闪）。

## 功能

- **F8** 开关，可在「选项 → 控制 → 按键绑定 → 自动补料（对接 mapart-feeder）」中改绑。
- **F7** 打开图形化设置界面（四个分页：交互 / 取料 / 超时 / 提示），改动即时保存，含「恢复默认」；全部用原版控件，不需要 ModMenu 或 Cloth Config。
- 缺口来源是**当前选中并启用**的投影的材料清单，不合并其它投影。
- 支持箱子/陷阱箱、木桶、放在世界中的潜影盒；双箱只算一次。
- 使用玩家真实交互距离与视线碰撞：不增加距离、不隔墙取物、不走路、不移动玩家。
- 只搬清单需要的材料；物品按「物品 + 组件」精确匹配，不会只按名字合并。
- 背包优先合并到未满的同种堆，再使用空格；不使用护甲格、合成格、副手作为落点。
- **同一容器批量 Shift 取料**：使用原版 `QUICK_MOVE`，在同一 tick 连续处理所有需要的源槽位；最后不足一组的缺口才精确拆分。
- 每次结算后会在聊天与操作栏提示**具体取到什么、各多少个**，例如：`已取 圆石×64、橡木木板×32（共 96 个）`。
- **取完立即关箱，核对在关箱之后**：结算请求与关箱在同一 tick 发出，服务端先回完整库存快照、再处理关箱，所以箱子不会为了等一次往返而一直敞开。
- **宁可停印也不乱印**：只要当前界面不是玩家背包（例如容器还开着），或鼠标上还拿着物品，Easy Place、投影打印机以及本 Mod 的放置/攻击**一律不执行**；关箱、光标清空后自动恢复。
- **不反复检查同一容器**：无料、正常取完都保留访问记录；离开该容器的交互范围（带 1 格缓冲）后才重新允许检查。因容量不足跳过的容器，仅在背包空间实际增加且能继续取物后允许重试。F8 关闭再开启可立即重查，切换投影或统计范围也会重置记录。
- **容器高亮（用缓存标注箱子）**：开启时给附近**已登记**的容器画框——**绿框**＝缓存里还有当前缺口需要的材料（并显示能拿的种类与数量），**黄框**＝还没勘察过、内容未知，**灰框**＝勘察过但没有所需的料；左上角同时列出最近的几项与距离。只标登记过的箱子，距离由 `highlightRange` 控制。
- **容器内容只在真正开箱、并拿到服务端完整库存后记录**，不隔空猜测；记录会自动过期（默认约 5 分钟）。
- 材料清单沿用上游语义：倍数 1 用 `missing`，大于 1 用 `total × 倍数`，再减去一次 `available`；用户忽略项保留。
- 容器缺料或打不开时进入冷却，不会来回反复开关。

## 安装

1. 备份存档，先在测试环境验证。
2. 保持已有的 Fabric API、Litematica、MaLiLib 不变；不需要 Printer。**mapart-feeder 是必需的**，否则没有任何可取料的容器。
3. 把 `feeder-restock-<版本>.jar` 放进游戏实例的 `mods` 目录（不要放 `-sources.jar`）。
4. 进入游戏，用 mapart-feeder 的 **K** 登记原料箱，选中并启用要打印的投影，按原来的方式开启 Easy Place，再按 **F8**。

启动、断线、切换维度后自动补料默认关闭，不会记住开启状态。

> **从旧版升级**：0.6.0 起 Mod ID、包名、配置文件都已改名。请先退出游戏，删除 `mods` 里旧的 `rail-restock-*.jar`，再放入新 JAR；旧的 `config/railrestock.json` 不再读取，可在 F7 里重新设置（默认值已按新行为调整）。

## 设置界面（F7）

游戏内按 **F7** 打开，改绑位置与开关在同一分类下。每项都是原版控件，鼠标点一下即生效并立刻写入 `config/feederrestock.json`；点「恢复默认」可还原全部默认值。

| 分页 | 内容 |
| --- | --- |
| 交互 | 无感开箱、开箱前提前暂停、取料后暂停、补料暂停上限、手动接管后等待 |
| 取料 | 扫描间隔、分批间隔、容器缓存有效期、取完后重查、容量不足重试、无料冷却 |
| 超时 | 开箱超时、同步超时、更新需求间隔 |
| 提示 | 高亮已登记容器、高亮距离、自动重算材料清单、聊天提示、操作栏状态 |

- 界面本身不需要 ModMenu、Cloth Config 等额外依赖。
- 打开界面会让正在进行的补料**自动暂停**（并安全关掉它开的容器），关闭界面后照常继续。
- 数值项是滑条，范围就是配置允许的合法区间，不会写出越界值。

## 配置

首次启动生成 `config/feederrestock.json`。多数项在游戏内按 **F7** 直接调整即可；手改文件请在退出游戏后进行。

| 字段 | 默认 | 说明 |
| --- | ---: | --- |
| `unobtrusiveInteraction` | `true` | 无感模式：隐藏自动打开的容器界面。设为 `false` 则显示箱子界面 |
| `autoRecountMaterialList` | `false` | 自动重算建筑缺失清单。默认关闭，本 Mod 不会自动触发统计 |
| `scanIntervalTicks` | 5 | 空闲时检查登记容器是否可交互的间隔 |
| `clickIntervalTicks` | 2 | 极端拆分超出单 tick 的 128 包预算时，继续下一批的间隔 |
| `openTimeoutTicks` | 40 | 开箱与完整库存等待上限 |
| `syncTimeoutTicks` | 60 | 预统计与确认等待上限 |
| `emptyContainerCooldownTicks` | 200 | 无料/打不开的容器，再次进入范围时的最小重试间隔 |
| `successCooldownTicks` | 20 | 容量不足时重试的最小间隔，仍须背包空间实际增加 |
| `containerRevisitTicks` | 600 | 已取完容器再次靠近时的最小重查间隔（默认 30 秒） |
| `recountIntervalTicks` | 200 | 空闲时更新建筑需求 |
| `manualPauseTicks` | 60 | 手动接管后的等待 |
| `preOpenPauseTicks` | 5 | 开箱前提前暂停打印的 tick 数（0 表示不开提前量） |
| `printPauseTicks` | 6 | 最后一次槽位操作后额外保持暂停的 tick 数，约 0.3 秒 |
| `visitPauseCapTicks` | 40 | 一次补料最多暂停打印多久（tick，约 2 秒） |
| `knowledgeExpireTicks` | 6000 | 已勘察容器内容的可信时长（约 5 分钟） |
| `highlightContainers` | true | 用缓存标注已登记容器：绿＝有料、黄＝未勘察、灰＝无所需 |
| `highlightRange` | 48 | 高亮的距离上限（格，可调 8–128） |
| `chatNotifications` | true | 聊天提示 |
| `actionbarStatus` | true | 空闲时的操作栏状态 |

20 tick 约为正常服务器 1 秒。

### 关于自动重算清单

`autoRecountMaterialList` 控制**是否由本 Mod 自动触发 Litematica 的材料统计**。每次统计 Litematica 自己都会在聊天里打一行「已添加任务」，并在 HUD 上跑进度——这是它的提示，不是本 Mod 发的，所以只能通过不触发统计来消除。

- **关闭（默认）**：本 Mod 不再调度任何统计任务，只用**已有的一次统计结果**计算缺口；建筑进度变化后缺口会偏大，可能多拿一点材料，需要你在 Litematica 里手动刷新一次清单来校正。
- **开启**：每次补料前、以及空闲时定期重算建筑缺失量，缺口最准。代价是会出现上述提示与 HUD 统计。

另外，每个投影**第一次**被本 Mod 读取时，Litematica 自己的懒加载仍会算一次（可能仍有一条提示），之后只要关闭该选项就不会再触发。

无论开关如何，补料成功后本 Mod 都会**静默**更新背包可用数量（这一步不触发 Litematica 提示，是防止重复搬料的关键）。

## 登记与选箱

- 只用 `config/mapartfeeder.json` 的 `containers` 数组（维度 + 坐标）；你在游戏里按 K 新登记的箱子，本 Mod 最多 1 秒后就能看到，不需要重启。
- **选箱顺序**：已知含有缺口原料的容器（按 `可用数量 × 64 ÷ (距离 + 1)`）→ 尚未开过的容器（按距离）→ 已知没有所需原料的容器直接跳过。
- **内容缓存**只在真正开箱并拿到服务端完整库存、或取料结算的完整同步后写入；取走时同步扣减，所以同一容器不会被反复当成还有料。
- **时效**：缓存默认 5 分钟（`knowledgeExpireTicks`）后失效并重新勘察；F8 关闭再开启、切换投影或统计范围会立即清空。
- 只读该文件；即使文件被写坏，最多一秒钟后回退到上一次成功解析的登记表。

## 已知边界

- 未打开的容器内容无法提前知道，必须真的打开并等服务端同步。玩家移动速度过快（鞘翅、疾跑跳跃等）时可能来不及完成一次开箱。
- 拆分光标堆前要求背包能容下**整个可能拾起的光标堆**，为意外关箱留归位余量。因此背包只剩零星空间时，可能暂时不取最后几个。
- 当前会话的完整同步请求依赖 1.21.11 原版的过期库存版本校正机制。若服务端插件拒绝该请求，会在 `syncTimeoutTicks` 后结束，不重开、不重放取物、不把预测计为成功。
- 已检查过的空箱若被外部重新加料，客户端无法隔空得知；缓存约 5 分钟后失效并重新勘察，也可以按 F8 关闭再开启立即重查。
- 服务端强制关箱、其他插件改写库存等情况下，原版行为仍可能影响最终归位。中断后本 Mod 不把预测当作成功。
- 非原版容器方块（模组箱子等）只在主手为空时才会被尝试，避免误放物品。
- 隐藏界面是**纯客户端**行为：服务器看到的就是一次正常开箱。请仅在允许自动补料的世界或服务器使用。

## 目录结构

仓库只保留源码、文档和脚本；构建产物、缓存都不进版本库。

```
feeder-restock/
├── src/main/java/dev/feederrestock/     模组源码
│   ├── client/        设置界面
│   ├── config/        配置读写
│   ├── integration/   Litematica / 投影打印机 / mapart-feeder 的反射适配
│   ├── logic/         纯逻辑（取料规划、选箱、暂停窗口等，都有单元测试）
│   ├── mixin/         注入点
│   └── runtime/       补料状态机与交互
├── src/main/resources/                模组元数据、Mixin 配置、中英文语言文件
├── src/test/java/                     单元测试与字节码守卫测试
├── tools/                             构建环境准备与排查脚本（见 tools/README.md）
├── dist/                              可安装的发布包（见 dist/README.md）
│   ├── <当前版本>/
│   └── archive/         历史版本留档
├── build.gradle / settings.gradle / gradle.properties
├── build.cmd                          Windows 构建入口
├── README.md / README.en.md / CHANGELOG.md / GAME_TEST_CHECKLIST.md / LICENSE
└── .gitignore
```

`build/`、`.gradle/`、`logs/` 是构建时自动生成的，删掉不影响任何东西——下次 `build.cmd` 会重建。Gradle 发行包与依赖缓存在**上一级会话目录**的 `.gradle-dist/`、`.gradle-user-home/`，不会写进项目，也不碰系统目录。

## 构建

Windows 下执行：

```bat
build.cmd build
```

首次需要 `tools\prepare.cmd` 准备隔离的 Gradle 发行包。构建把 Gradle 缓存、Java 用户目录与临时目录都放在工程的上级（会话）目录，不污染系统目录。

产物：`build/libs/feeder-restock-<版本>.jar`；要分发的安装包放到 `dist/<版本>/`。

## 备注

- 材料清单通过反射访问 Litematica 的公开 getter，**不依赖 `toNbt`/`toJson`** 这类版本相关的持久化接口，也不占用 Litematica 的单槽 completion listener。
- 本项目不包含 Litematica / MaLiLib / Fabric API / mapart-feeder，也不修改它们的文件。
